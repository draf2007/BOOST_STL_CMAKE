- Range = книга (m_l, m_r); итератор = закладка (m_current + ссылка на владельца m_owner, чтобы знать границы; friend class const_iterator даёт доступ к приватным полям).
- Золотой шаблон: 5 using-типов (iterator_category, value_type, difference_type, pointer, reference) + Big 5 операторов. Правила: operator* — всегда const; operator++ — никогда не const; постфиксный ++(int) реализуется через префиксный; operator== и != — всегда const; сравнивать только значимые поля.
- Для range-based for нужны begin()/end() (и cbegin()/cend()); типы-алиасы обязательны для алгоритмов STL (std::iterator_traits).
- Итоговый артефакт: ГИБРИДНЫЙ шаблон Range (от преподавателя: m_l/m_r, friend, два конструктора Range(r) и Range(l,r), умное двунаправленное движение в operator++; от нас: полные STL-типы, forward_iterator_tag, чистая структура).

## 🧠 Ключевые концепции, которые я усвоил

### Из lvalue/rvalue:
- lvalue — именованный объект с адресом (коробка с именем)
- rvalue — временное значение без имени (вещь без коробки)
- `const T&` принимает и lvalue, и rvalue
- `T&` принимает только lvalue
- `T&&` (вне шаблона) принимает только rvalue

### Из move-семантики:
- Copy — выделение новой памяти, копирование данных (медленно)
- Move — передача указателя, обнуление источника (быстро)
- `std::move` НЕ перемещает, а "превращает" lvalue в rvalue
- `noexcept` критичен для move-конструктора
- Правило пяти: если реализовал один метод — реализуй все пять
- Правило нуля: в 90% случаев не пиши ничего

### Из универсальных ссылок:
- `T&&` в шаблоне — это универсальная ссылка (не rvalue-ссылка!)
- Для lvalue: `T` выводится как `int&`, итог `int&`
- Для rvalue: `T` выводится как `int`, итог `int&&`
- Правило схлопывания: `& + &` = `&`, `&& + &&` = `&&`
- Имя всегда lvalue, даже если тип rvalue-ссылка

### Из perfect forwarding:
- Универсальные ссылки принимают любую категорию
- `std::forward` передаёт дальше с сохранением категории
- Внутри функции параметр всегда lvalue (у него есть имя!)
- Без `std::forward` любая передача = копирование

### Из шаблонов классов (добавлено в текущем чате):
- Шаблон класса = чертёж, компилятор генерирует реальный класс при инстанцировании
- Тип нужно указывать явно: `Box<int>` (кроме C++17 CTAD)
- Полная специализация — для конкретного типа (`template<> class Box<int>`)
- Частичная специализация — для паттерна типов (`template<typename T> class Box<T*>`)
- CTAD (C++17) — компилятор выводит тип из аргументов конструктора

### Из вариативных шаблонов классов (добавлено в текущем чате):
- Вариативный шаблон = шаблон с произвольным числом типов (`typename... Types`)
- Parameter pack = набор типов, который можно "раскрыть" через `...`
- `sizeof...(Types)` = количество типов в pack
- Нельзя просто написать `Types... values;` — нужно наследование или композиция
- Два способа хранения: рекурсивное наследование (матрёшка) или множественное наследование (многодетный родитель)

### Из std::tuple (добавлено в текущем чате):
- `std::tuple` = variadic шаблон класса для хранения разных типов
- Создание: явные типы, `std::make_tuple`, CTAD (C++17)
- Доступ: `std::get<I>` (по индексу) или `std::get<T>` (по типу, если уникален)
- Structured bindings (C++17) — самый удобный способ распаковки
- `std::tie` — старый способ, полезен с `std::ignore`
- Сравнение работает лексикографически
- Tuple можно использовать как ключ в `std::map`
- `std::apply` — вызывает функцию с аргументами из tuple

## ⚠️ Важные нюансы, которые я понял

### Из предыдущих чатов:
- `std::make_unique` создаёт объект `unique_ptr`, а не сырой указатель
- Функция-заглушка в вариативных шаблонах должна иметь совместимый тип возврата
- `is_lvalue_reference_v<T>` = false НЕ значит, что T — это rvalue-ссылка (T может быть просто `int`)
- `test(5)` с `void test(int& a)` — НЕ скомпилируется (не-const lvalue-ссылка не принимает rvalue)
- Правило нуля — лучший выбор в современном C++ (используй умные указатели)
- `std::forward` без универсальной ссылки — ошибка дизайна

### Из текущего чата (добавлено):
- **`const std::string&&` — это НЕ move-конструктор!** `const` запрещает изменять объект, поэтому перемещение невозможно. Правильно: `std::string&&` (без const).
- **Move-конструктор должен принимать НЕ-const rvalue-ссылку**, чтобы можно было "забрать" данные из источника.
- **Фабрика объектов** — это любой код (функция, метод, класс), основная задача которого — создавать объекты. Фабрика отделяет процесс создания от места использования.
- **Приватный конструктор + публичные статические методы** = паттерн "Фабричный метод" для контроля создания объектов.
- **Формулы конвертации температур:**
  - K → C: `C = K - 273.15` (не 273.5!)
  - F → C: `C = (F - 32) × 5/9` (не `(F-32)*0.5`!)
- **CTAD (C++17)** работает только если есть подходящий конструктор. Если конструкторов несколько или они неоднозначны — нужно указывать тип явно.
- **`std::get<I>` требует константного индекса**, потому что типы элементов разные, и компилятор должен знать на этапе компиляции, какой тип возвращать.
- **Structured bindings** работают не только с tuple, но и с `std::pair`, структурами, массивами.

## 🧠 Ключевые концепции, которые я усвоил

### Из lvalue/rvalue:
- **lvalue** — именованный объект с адресом (коробка с именем)
- **rvalue** — временное значение без имени (вещь без коробки)
- `const T&` принимает и lvalue, и rvalue
- `T&` принимает только lvalue
- `T&&` (вне шаблона) принимает только rvalue

### Из move-семантики:
- **Copy** — выделение новой памяти, копирование данных (медленно)
- **Move** — передача указателя, обнуление источника (быстро)
- `std::move` НЕ перемещает, а "превращает" lvalue в rvalue
- `noexcept` критичен для move-конструктора
- Правило пяти: если реализовал один метод — реализуй все пять
- Правило нуля: в 90% случаев не пиши ничего

### Из универсальных ссылок:
- `T&&` в шаблоне — это **универсальная ссылка** (не rvalue-ссылка!)
- Для lvalue: `T` выводится как `int&`, итог `int&`
- Для rvalue: `T` выводится как `int`, итог `int&&`
- Правило схлопывания: `& + &` = `&`, `&& + &&` = `&&`
- Имя всегда lvalue, даже если тип rvalue-ссылка

### Из perfect forwarding:
- Универсальные ссылки **принимают** любую категорию
- `std::forward` **передаёт дальше** с сохранением категории
- Внутри функции параметр всегда lvalue (у него есть имя!)
- Без `std::forward` любая передача = копирование

## ⚠️ Важные нюансы, которые я понял

1. **`std::make_unique`** создаёт **объект `unique_ptr`**, а не сырой указатель
2. **Функция-заглушка** в вариативных шаблонах должна иметь **совместимый** тип возврата
3. **`is_lvalue_reference_v<T>` = false** НЕ значит, что T — это rvalue-ссылка (T может быть просто `int`)

# Контекст чата: Изучение умных указателей в C++

## 1. Цель обучения
Пользователь изучает современные умные указатели C++ (`std::unique_ptr`, `std::shared_ptr`, `std::weak_ptr`) с нуля. Основной упор делается на построение ментальной модели, понимание RAII и разницу между владением и наблюдением.

## 2. Ключевые концепции, которые уже пройдены

### Базовая теория (RAII)
- Умный указатель — это класс-обертка над сырым указателем (`T*`), который автоматически вызывает `delete` в своем деструкторе.
- Использование «голого» `new` считается плохой практикой; вместо него используются фабрики `std::make_unique` и `std::make_shared`.

### std::unique_ptr (Эксклюзивное владение)
- **Ментальная модель:** Личная зубная щетка. Владелец только один.
- **Свойства:** Нельзя копировать, можно только перемещать (`std::move`). После перемещения исходный указатель становится `nullptr`.
- **Передача в функции:** 
  - Если функция должна забрать объект навсегда: передача по значению + `std::move`.
  - Если функция просто использует объект: передача по ссылке (`Engine&`) или константной ссылке. При этом владение не теряется.

### std::shared_ptr (Совместное владение)
- **Ментальная модель:** Съемная квартира с группой арендаторов. Объект удаляется только когда уходит последний жилец.
- **Свойства:** Есть счетчик ссылок (reference count). Копирование увеличивает счетчик, уничтожение — уменьшает.
- **Особенности:** `std::make_shared` выделяет память одним блоком (объект + контрольный блок), что эффективнее, чем `new` + `shared_ptr`.

### Практические навыки пользователя
- Пользователь успешно пишет код, используя `auto` и `make_...` функции.
- Понимает разницу между операторами `->` (для указателей) и `.` (для ссылок/объектов).
- Проводит эксперименты с областью видимости `{}`, чтобы проверить работу счетчиков ссылок.

## 3. Текущий статус и ошибки
- Пользователь понял механику `unique_ptr` и `shared_ptr`.
- Была исправлена ошибка при передаче объекта в функцию: переход от передачи владения (`std::move`) к передаче ссылки (`*ptr`), что позволило сохранить владение у вызывающей стороны.
- Исправлена синтаксическая ошибка: использование `.` вместо `->` при работе со ссылками.

## 4. Следующий шаг
- Переход к изучению **`std::weak_ptr`**.
- **Задача:** Разобрать проблему циклических ссылок (когда два `shared_ptr` ссылаются друг на друга и никогда не удаляются) и показать, как `weak_ptr` решает эту проблему, выступая в роли «наблюдателя», который не увеличивает счетчик ссылок.

## 2. Ключевые темы обсуждения

### Шаблонные функции (Function Templates)
*   **Определение:** Позволяют писать обобщенные алгоритмы, работающие с разными типами данных. Компилятор генерирует конкретные версии функции (инстанцирование) при вызове.
*   **Синтаксис:** `template <typename T>` (или `class T`).
*   **Пример из методички (Листинг 8.1):** Функция `max`.
    ```cpp
    template <typename T>
    T max(T a, T b) { return a > b ? a : b; }
    ```
*   **Перегрузка шаблонов:** Можно создавать специализированные версии для конкретных типов (например, для `const char*`, чтобы сравнивать строки через `strcmp`, а не адреса).
*   **Важно:** Код шаблона должен быть виден компилятору в точке вызова (обычно пишется в `.h` файлах).

### Шаблонные классы (Class Templates)
*   **Определение:** Автоматизируют создание классов для разных типов. Основа для будущих контейнеров.
*   **Параметры:**
    *   Типовые: `typename T`
    *   Нетиповые (константы): `int size`
*   **Пример из методички (Листинг 8.2-8.3):** Класс `Stack` (стек ограниченного размера).
    ```cpp
    template <typename T, int size>
    class Stack {
        T stk[size];
        int top;
    public:
        Stack();
        void Push(const T&);
        // ...
    };
    ```
*   **Реализация методов вне класса:** Требует повторения заголовка шаблона и указания параметров в имени класса:
    ```cpp
    template <typename T, int size>
    void Stack<T, size>::Push(const T& x) { /*...*/ }
    ```
*   **Использование:** `Stack<int, 10> iStack;`, `Stack<char, 26> cStack;`.

## 3. Важные нюансы из методички
1.  **Где хранить код:** Шаблоны обычно полностью реализуются в заголовочных файлах, так как компилятору нужно видеть тело шаблона для генерации кода.
2.  **Специализация:** Возможность создать особую реализацию для конкретного типа (полная или частичная специализация).
